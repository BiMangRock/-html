# 카드 결투 — 서버 + 로그인 + 계정별 저장 + 카드 컬렉션 + 상점 + 유저 대전 (1~6단계)

기존 단일 HTML(`v114_adventure6.html`)을 파일로 나누고, 회원가입/로그인이 있는 서버를 붙인 버전입니다.
**게임 자체는 그대로**이고, 골드·내 덱·모험 클리어 기록은 이제 **로그인한 계정별로 서버(SQLite)에 저장**됩니다. 어느 기기에서 로그인해도 같은 데이터가 보입니다. 또 **가진 카드로만 내 덱을 만들 수 있고**(카드 컬렉션), **상점에서 카드 팩을 열어 카드를 모을 수 있습니다**(5단계).

## 실행 방법

1. [Node.js](https://nodejs.org) **22.13 이상**(22 LTS 또는 24) 설치 — SQLite 가 Node 에 내장돼 있어서 따로 설치할 게 없습니다
2. 이 폴더에 **기존 프로젝트의 `images/` 폴더를 통째로 복사** (카드 이미지는 이 zip에 없습니다). 유저 대전 화면용 이미지는 이미 `images/pvp/` 에 들어 있으니, 복사할 때 이 폴더를 덮어쓰지 말고 **합쳐서** 넣으세요
3. 터미널에서 이 폴더로 이동한 뒤:
   ```
   npm install
   npm start
   ```
4. 브라우저에서 http://localhost:3000 → 회원가입 → 게임 시작

> 실행할 때 `ExperimentalWarning: SQLite is an experimental feature` 라는 노란 경고가 한 줄 뜰 수 있는데, 정상입니다.

> 파일을 더블클릭해서 여는 방식(`file://`)은 이제 안 됩니다. 항상 `npm start` 로 서버를 켜고 접속하세요.

## API

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/signup` | `{username, password}` → 가입 + 자동 로그인 |
| POST | `/api/login`  | `{username, password}` |
| POST | `/api/logout` | 로그아웃 |
| GET  | `/api/me`     | 내 정보 (로그인 안 했으면 401) |
| GET  | `/api/health` | 서버 상태 |
| GET  | `/api/save`   | 내 저장 데이터 전체 `{wallet, deck, collection, adventure}` (게임 시작 때 한 번). 처음이면 시작 골드 100 + 스타터 카드로 만들어 줌 |
| PUT  | `/api/wallet` | 골드 저장 `{gold,pool,poolDay,bet,rev}` — `rev` 가 서버와 다르면 409 (다른 기기에서 먼저 저장됨) |
| PUT  | `/api/deck`   | 내 덱 저장 `{deck:[카드이름×30]}` — 30장·같은 카드 2장·존재하는 카드·**내가 가진 카드만** 허용 |
| POST | `/api/adventure/clear` | 보스 첫 클리어 기록 `{bossId}` (이미 있으면 첫 시각 유지) |
| GET  | `/api/shop` | 상점 정보: 가격·확률·환급액·천장 진행도·최근 개봉 기록 20개 |
| POST | `/api/shop/open` | 팩 개봉 `{count:1~10, rev}` → 골드 차감 + 카드 지급 + 환급을 한 번에 처리하고 `{packs, spent, refund, wallet, collection, pity}` 반환. 골드 부족이면 400, `rev` 가 다르면 409 (같은 요청을 두 번 보내도 한 번만 처리됨) |

저장 API 는 전부 로그인 필수이고, 항상 **내 계정** 기준으로만 읽고 씁니다.

- 아이디: 3~16자, 한글·영문·숫자·밑줄 (대소문자 구분 없이 중복 검사)
- 비밀번호: 8~72자
- 비밀번호는 scrypt 해시로 저장, 세션은 httpOnly 쿠키(30일) + DB에는 토큰의 해시만 저장
- 실패 횟수 제한: 아이디당 10분에 8회, IP당 10분에 30회

## 원본에서 바꾼 점 (동작 변화 없음)

- `<script>` 4개 + `<style>` 를 파일로 분리하고, `CARD_POOL` 은 `engine` 에서 `cards.js` 로 따로 뺐습니다.
- **`runeOf`, `RUNE_NAME`, `RUNE_ORDER` 를 ui → engine 으로 이동.** 엔진이 이 함수를 쓰는데 원래 화면 코드에 있어서, 서버(Node)에서 엔진을 돌리면 에러가 나는 숨은 의존성이었습니다.
- CSS 안의 이미지 경로를 `images/…` → `/images/…` 로 바꿨습니다 (CSS 파일 위치가 달라져서).
- `engine.js`·`cheats.js` 맨 위에 Node용 `require` 연결 한 줄씩, `cards.js`·`economy.js`·`cheats.js` 맨 아래에 `module.exports` 를 추가했습니다.
- 검증: 같은 난수 시드로 원본 엔진과 분리한 엔진에 봇 대전 100판씩 돌렸을 때 결과가 완전히 같았습니다. 가상 브라우저(jsdom)에서 원본/분리본 모두 스크립트 에러 없이 로드되는 것도 확인했습니다.

## 3단계에서 바뀐 점

- **저장 위치**: 골드 → `wallets`, 내 덱 → `decks`, 보스 클리어 → `adventure_progress` 테이블 (`data/game.db`).
- **동작 방식**: 게임 화면이 열릴 때 서버에서 한 번 불러오고("불러오는 중…"), 이후 변경은 바로 서버로 보냅니다. 게임 코드는 예전처럼 동기로 읽고 씁니다 (`Economy` 의 저장소를 `serverstore.js` 가 대체).
- **연결이 끊기면**: 위쪽에 노란 알림이 뜨고 3초마다 다시 보냅니다. 못 보낸 변경이 있는 채로 탭을 닫으려 하면 브라우저가 경고합니다.
- **두 기기/탭 동시 사용**: 골드에는 저장 번호(`rev`)가 있어서, 다른 곳에서 먼저 저장했으면 이 탭은 저장을 멈추고 "새로고침해 주세요" 알림을 띄웁니다 (조용히 덮어쓰지 않음).
- **새 계정**은 시작 골드 100 · 추천 덱 · 클리어 기록 없음으로 시작합니다. **기존 브라우저(localStorage)에 있던 골드·덱·클리어 기록은 자동으로 옮겨지지 않습니다.**
- **배팅 도중 종료**는 예전처럼 몰수 처리됩니다 (배팅 금액이 서버에 저장된 채 남아 있다가 다음 접속 때 잃은 것으로 정리).

## 4단계: 카드 컬렉션

- **희귀도**: 286장 전부에 `rarity` 를 지정했습니다 (`cards.js`). 등급은 일반 → 희귀 → 특급 → 전설.
  분포: 일반 130 · 희귀 69 · 특급 42 · 전설 45. 원래 20장에 적혀 있던 등급은 그대로 두고, 나머지는 **제가 정한 기준(이름 있는 인물 카드는 전설, 그 외는 코스트·효과 복잡도 순으로 나눔)** 으로 채웠습니다. 게임 밸런스에 맞게 마음대로 고치세요 — 카드 줄의 `rarity:'희귀'` 만 바꾸면 되고, `npm test` 가 빠진 카드가 없는지 확인해 줍니다.
- **스타터 카드**: 새 계정(또는 3단계까지 쓰던 기존 계정의 첫 접속)은 **일반 카드 전부 2장씩 + 추천 덱 카드**를 받습니다. 딱 한 번만 지급됩니다 (`collection_init` 표시).
- **덱 에디터**(내 덱 편집): 가진 장수까지만 넣을 수 있고, 못 가진 카드는 어둡게 🔒 표시됩니다. 카드마다 등급과 `보유 N장`이 보이고, 위쪽 탭에 등급별 필터와 `보유 카드만` 버튼이 생겼습니다.
- **서버도 검사**: 저장된 덱이 보유 카드와 안 맞으면(조작이든 보유 카드가 줄었든) 불러올 때 추천 덱으로 대체됩니다. 덱 저장 요청도 서버가 보유 여부를 다시 확인합니다.
- **그대로인 것**: AI·보스 덱, 보스 덱 편집, 테스트 모드 덱은 전체 카드풀을 계속 씁니다.

### 카드 지급 도구 (테스트용)

상점을 거치지 않고 터미널에서 직접 카드를 지급할 수 있습니다 (테스트·운영 보정용). 서버가 켜져 있어도 되고, 지급 후 브라우저를 새로고침하면 반영됩니다.

```
node server/grant.js 아이디 all             # 모든 카드를 최소 2장씩
node server/grant.js 아이디 rarity:전설 2   # 전설 전부 2장씩 (희귀 / 특급 / 일반도 같은 방식)
node server/grant.js 아이디 "데스윙" 1      # 카드 한 장
```
"최소 N장"이라서 이미 더 갖고 있으면 그대로 둡니다.

## 5단계: 상점 (팩 개봉)

메인 메뉴의 **🛒 상점**에서 카드 팩을 엽니다.

- **팩**: 1팩 **100골드**, 카드 **5장**. 한 번에 1팩 또는 5팩(서버는 최대 10팩까지 받음).
- **확률(카드 1장당)**: 일반 70% · 희귀 22% · 특급 6.5% · 전설 1.5%. 같은 등급 안에서는 모든 카드가 같은 확률입니다.
- **희귀 보장**: 한 팩에 희귀 이상이 하나도 없으면 마지막 한 장을 희귀 이상으로 다시 뽑습니다.
- **중복 환급**: 같은 카드를 **2장** 가지면(= 덱에 넣을 수 있는 최대 장수) 그다음부터 나온 같은 카드는 컬렉션에 안 들어가고 골드로 환급됩니다. 환급액: 일반 5 · 희귀 15 · 특급 40 · 전설 100. 한 팩 안에서 같은 카드가 두 번 나온 경우도 똑같이 처리합니다.
- **천장**: 특급 이상이 **10팩** 연속 안 나오면 다음 팩에 특급 이상 1장, 전설이 **30팩** 연속 안 나오면 다음 팩에 전설 1장이 확정됩니다. 확정은 그 팩에서 가장 낮은 등급의 카드 한 장을 올려서 하므로, 이미 나온 좋은 카드를 깎지 않습니다. 카운터는 계정별로 저장되고, 상점 화면에 "확정까지 N팩"으로 보입니다.
- **개봉 연출**: 팩 탭 → 흔들림 → 카드 뒷면 5장 → 카드를 눌러 한 장씩 뒤집기(낮은 등급부터, 가장 좋은 카드가 마지막). 특급·전설은 빛과 파동 효과가 나옵니다. NEW / 중복 환급 표시, "모두 뒤집기" 버튼, 5팩은 마지막에 결과 요약이 나옵니다.
- **개봉 기록**: 팩 한 개마다 `pack_log` 테이블에 시각·가격·나온 카드(등급·신규/중복)·환급액·천장 여부가 남고, 상점의 "📜 최근 개봉 기록"에서 최근 20팩을 볼 수 있습니다.
- **서버가 전부 처리**: 난수는 서버의 `crypto.randomInt`, 골드 차감 + 카드 지급 + 천장 + 기록은 한 트랜잭션입니다 (중간에 실패하면 전부 취소 — 골드만 빠지고 카드는 안 오는 일이 없음). 브라우저는 몇 팩인지만 보내고 결과를 연출만 합니다.

수치를 바꾸고 싶으면 **`public/js/shop.js` 맨 위의 `SHOP`** 만 고치면 됩니다 (가격·장수·확률·보장·천장·환급액). 서버와 상점 화면의 확률표가 같은 값을 쓰고, `npm test` 가 확률 합계와 천장 동작을 다시 확인합니다.

> ⚠ **골드 자체는 아직 클라이언트가 계산합니다** (6단계 전까지). 팩 개봉은 서버가 하지만, 지갑 저장 API(`PUT /api/wallet`)가 아직 골드 값을 그대로 받아 주기 때문에 개발자 도구로 골드를 올린 뒤 팩을 사는 조작은 막지 못합니다. 6단계에서 골드를 서버가 직접 계산하게 바꿉니다.

## 6단계: 유저 대전 (PvP)

모드 선택 → **👥 유저 대전** → 대전 상대 찾기. 대기 중인 다른 사람과 자동으로 붙습니다. **저장된 내 덱**으로 싸우고, 이기면 **50골드**를 받습니다. (랭크는 아직 없음)

- **서버가 판을 진행합니다.** 손패·덱 순서·난수는 서버만 갖고, 브라우저는 "행동"만 보냅니다. 서버가 엔진으로 검증·적용하고, 각자에게는 자기 시점의 화면만 보냅니다 (상대 손패·덱 구성·상대가 얻은 카드 이름은 가려짐).
- **통신**: 서버 → 브라우저는 SSE(`GET /api/pvp/stream`), 브라우저 → 서버는 POST. 추가 설치 없이 동작하고 끊기면 자동 재접속합니다.
- **시간 제한** (`public/js/pvp.js`): 한 턴 60초 · 멀리건 30초. 시간이 지나면 턴이 자동으로 넘어가고, **연속 3번** 넘어가면 패배. 시간이 지났을 때 선택(발견·대상)이 남아 있으면 첫 번째 선택지로 처리합니다.
- **연결 끊김**: 60초 안에 돌아오면 이어서 합니다(새로고침 포함). 못 돌아오면 패배, 둘 다 끊기면 무효 판(전적·보상 없음). 상대가 끊기면 화면에 남은 시간이 뜹니다.
- **보상**: 이기면 **매 판 50골드**가 서버에서 바로 지갑에 들어갑니다 (판 기록과 한 트랜잭션). **횟수·턴 수·상대 제한은 없습니다** (일찍 끝난 판도, 하루 몇 판이든, 같은 상대와 반복해도 보상). 무승부·무효 판만 보상이 없습니다. 금액은 `public/js/pvp.js` 의 `WIN_GOLD`.
- **전적**은 `pvp_matches` 테이블에 판마다 한 줄씩 남습니다 (무효 판은 전적에서 제외).

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/pvp/stream` | 계속 열려 있는 SSE. 접속하면 현재 상태(대기·진행 중인 판)를 먼저 보내 줌. 한 계정 최대 4개 |
| GET | `/api/pvp/status` | `{state:'idle'\|'queue'\|'match'}` |
| POST | `/api/pvp/queue` · `/api/pvp/cancel` | 대기열 참가 · 취소 |
| POST | `/api/pvp/mulligan` | `{matchId, ids}` 바꿀 시작 카드 |
| POST | `/api/pvp/action` | `{matchId, seq, action}` — `seq` 가 서버와 다르면 409 (낡은 화면) |

새 파일: `server/pvp-core.js`(대기열·판 진행·시간·끊김) · `server/pvp.js`(API) · `server/pvp-db.js`(덱 불러오기·보상·한도·전적) · `server/wallet.js`(지갑 도우미, saves.js 에서 분리) · `public/js/pvp.js`(수치) · `public/js/pvpclient.js`(대전 화면). 테스트: `test-pvp-db.js`, `test-pvp.js`.

⚠ 서버를 **한 대**(프로세스 하나)로 돌린다는 전제입니다. 대기열과 진행 중인 판이 메모리에 있어서, 서버를 재시작하면 진행 중인 판은 사라집니다(그 판은 기록·보상 없음).

## 아직 안 된 것 (다음 단계)

- AI 대전·모험의 승패·골드 **판정은 아직 클라이언트**가 합니다 (유저 대전은 서버 판정). 서버는 골드 값이 형식에 맞는지(정수, 0 이상, 풀 20~300)만 확인하고, 얼마를 벌었는지는 검증하지 않습니다 → 개발자 도구로 골드를 조작할 수 있습니다. → 6단계에서 서버 판정으로 이전 (팩 구매 때 쓰는 골드도 이때 같이 서버 기준이 됩니다)
- **테스트 모드 설정**과 **보스 편집 내용(개발자 전용)** 은 아직 브라우저 localStorage 입니다 (게임 진행 데이터가 아니라 개발 도구라서 남겨 뒀습니다).
- 상점에서 **천장·중복 환급은 있지만 가루 제작은 아직 없습니다** (나중에)

## 모바일 (v115)

- `public/js/mobile.js` — 터치 기기에서 첫 터치 때 전체화면 + 가로 고정을 시도합니다 (안드로이드 크롬). 메뉴 오른쪽 위 **⛶ 전체화면** 버튼으로도 켜고 끌 수 있습니다.
- 아이폰 Safari 는 웹페이지의 전체화면·방향 고정을 막아 둡니다. 세로로 들고 전투에 들어가면 "가로로 돌려 주세요" 안내가 덮입니다. **홈 화면에 추가**하면 주소창 없이 열립니다.
- 가로 폰 화면(높이 540px 이하)에서는 전투 화면이 하스스톤 식(왼쪽 영웅 · 가운데 필드 · 오른쪽 턴 종료 · 아래 손패)으로 바뀌고, 전투 기록은 오른쪽 위 📜 버튼으로 엽니다. PC 화면은 그대로입니다.
- `public/manifest.webmanifest` + `public/icons/` — 홈 화면 앱 설정(가로 고정·전체화면). 설치형 앱 동작은 HTTPS 주소에서만 됩니다.
